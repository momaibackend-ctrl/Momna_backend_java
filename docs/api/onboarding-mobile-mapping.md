# Onboarding: app screens → Java Flow API fields (ONB-API-01)

Generated on 26.11.2026. Sources:
- the app's content extract `momna-mobile/tools/onboarding-content/onboarding-content.json` (Figma);
- this repository's flow definitions (`StandardFlowDefinitionCatalog`) and canonical field registry.

Screens and steps are aligned in order, by type and number of options.

**How to answer.** Start or resume the flow with `POST /api/v1/flow-instances` (`flowType` `PERIOD_ONBOARDING`, `period`), then `PUT /api/v1/flow-instances/{id}/answers/{fieldId}` for the current step only. The body is `{expectedDefinitionVersion, expectedRevision, mode: SUBMIT | CHANGE, value}`, with an `Idempotency-Key` header.

The current step names its field and what an answer may be:
- `dataType`;
- `options` — the machine codes;
- `requiredKeys`;
- `perChild`;
- `maxLength`.

Any other value is refused with 422 `INVALID_FIELD_VALUE`. Option codes follow the order of the app's options unless a row says otherwise. A skipped question goes to `POST …/steps/{stepId}/skip`, never as a made-up answer.

## Notes for the app

- **Pregnancy dating.** «What is the easiest way for you to enter how far along you are?» answers `onboarding.pregnancy.dates_method`. The bottom sheet opened from that answer gives the next step:
  - weeks → `gestational_weeks` (NUMBER 1–42);
  - due date → `edd` (DATE);
  - last period → `lmp` (DATE).

  These steps are conditional on the method, so the server asks only the one that applies.
- **More than one baby.** When there is more than one baby, the server replaces the single-baby steps with per-baby ones: `child_status_by_child`, `delivery_by_child`, `feeding` (perChild), and the breast-milk clarification. The app shows the same screens once per baby and sends `{"1": code, "2": code, …}`.
- **No birth date.** `time_since_birth_approx` is asked only when the birth date is skipped.
- **Server only** marks codes the server accepts but the app does not show. They need no change in the app.
- A field the app never shows must be skipped with `POST …/steps/{stepId}/skip`, never answered with a made-up value.
